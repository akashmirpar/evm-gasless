EIP-7702 · BSC, Base, Arbitrum

Transactions without gas.

A user holding only an ERC-20 signs once. An operator pays the gas, runs the user's intent, and is paid a small fee in the token the user already holds. No native balance, no faucet, no second wallet.

How it works

  1. The user delegates their address

    An EIP-7702 authorization points the user's own address at the GaslessDelegate contract. Their balances and history stay where they are; the address gains the contract's execution logic.

  2. They sign one EIP-712 batch

    The batch names a fee transfer to the operator's treasury, then the user's own operations. Every recipient, amount and byte of calldata is under the signature; nothing can be reordered or altered.

  3. The operator broadcasts and pays

    The operator submits the type-4 transaction and covers the gas. The fee leg must succeed. The user's intent runs in an isolated self-call: if it reverts, the fee still settles and the nonce still advances.

  4. Any ERC-20 can be the fee token

    If the user's token is not one the operator accepts directly, the fee leg becomes an approve and an on-chain swap into one that is. Same transaction, same signature.

Two zones, one signature

The structure of a signed batch. The boundary between the zones is itself part of what the user signs.

What the relayer guarantees

One address on every chain

The delegate is deployed with CREATE2 from a frozen salt and a pinned toolchain, so it sits at the same address on every chain. Integrators reference one value; the deploy script refuses to run if the compiled bytecode would move it.

Signed once, persisted, then broadcast

The signed transaction is stored before it is sent. A retry re-sends the same bytes; it never re-signs with a fresh nonce, so a transaction with no receipt cannot become two.

Bounded retries

A request that keeps failing backs off from 30 seconds to 5 minutes and then terminates. Nothing spins at cron cadence against an RPC.

No-loss ceiling

A quote is refused when the fee could not cover the network cost at the ceiling gas price. The operator cannot be made to settle at a loss when priority fees spike.

Integrating

Four endpoints under /gasless/transactions. Every route takes an integrator key on the x-api-key header.

POST …/estimateFee quote in the user's chosen token.
POST …Build the batch: EIP-712 typed data to sign, plus a requestId.
POST …/:requestId/submitThe user's signature and EIP-7702 authorization. The relayer broadcasts.
GET …/:requestIdStatus, transaction hash, failure reason.
